# 第3ラウンド（最終回）検証報告：株価指数の情報を加えた2つの仮説

対象：histdata の1分足から作った足（EST＝UTC−5 固定、夏時間なし）。FX は bars_full（2005〜2024年の連続データ）、株価指数は bars_idx（2010-11〜2024-12）。コストは第0〜2ラウンドと同じ COST_PIPS（往復、変更なし）。スワップ（金利差調整額）は含めていません。
採点期間：2011-10-01〜2024-12-31。IS＝2011-10〜2017-12、OOS＝2018-01〜2024-12。

## 1. 結論

- **事前に固定した4つの案（H-A a／b、H-B a／b）は、すべて不合格です。** 判定基準を全部満たした案はありません。H-B の「取引数 N≥100」だけは満たしましたが、これは取引の回数の条件で、利益の条件ではありません。
- **H-A（株価の上昇局面だけクロス円などを買う）：フィルターを付けると、常に買い持ち（ベンチマーク）より悪くなりました。**
  - 年率8%ボラ換算の Sharpe は、グループA 0.12（買い持ち 0.31）、グループB −0.04（買い持ち 0.08）です。variant b はどちらのグループでもマイナスでした。
  - 原因ははっきりしています。S&P500 が200日平均を下回っている日（下落局面）のほうが、買い持ちの成績は**良かった**のです。グループAで年率 +11.5%、上昇局面の日は +1.4% でした。株価が大きく下がった後のクロス円の戻りを、フィルターが取り逃がしています。
- **H-B（月末ロンドン16時フィックス前のドル売買）：手数料前でもほぼゼロでした。** 1回あたりの平均は、variant a で −0.010R、variant b で +0.025R です。往復コストが約 0.03R なので、コスト後はマイナスになります。4ペアのうちプラスは1ペアだけでした。
- 合格案がないため、事前の手順どおり、次の作業は**行っていません**。
  - 取引しない条件の検討
  - 5%／8%運用シミュレーション、ブートストラップ
  - EA（r3_EA.mq5）の作成
  - 結果を見た後にパラメータやルールを変えること
- これで3回の繰り返しの上限に達しました。**このデータとコスト条件では、合格基準を満たす売買ルールは見つかりませんでした。**

## 2. 第3ラウンドの位置付け

- 最終回（3回目）です。複数のルールを試すほど、偶然良く見えるルールが出やすくなります（多重検定）。それを抑えるため、繰り返しは最初から3回までと決めていました。
- 第0〜2ラウンドでは、価格だけを使うルールを40以上試しました（ボリンジャー/RSI ダイバージェンス、ドンチアン、EMA、時系列モメンタム、RSI(2)、スクイーズ、押し目、セッションブレイク、通貨の横断的モメンタム/リバーサル、時間帯の季節性）。どれも、銘柄と期間を変えるとコスト後に残りませんでした。
- 「FX の価格だけでは、もう新しい情報がない」と判断しました。そこで今回は、**それまで使っていなかった株価指数（S&P500、DAX、FTSE100、日経225、ASX200）**を加えました。経済的な理由がある2つの仮説だけを事前に登録し、パラメータは調整していません。
  - H-A：リスクオン（株高）の局面では、高金利通貨買い・円売り（キャリー）が利益を出しやすい、という考え方です。
  - H-B：Melvin & Prins (2015) の月末ヘッジ調整フローです。米国株が他国株より上がった月は、外国の投資家が月末にドルのヘッジを増やす（ドルを売る）ので、ロンドン16時フィックスに向けてドルが弱くなる、という考え方です。

## 4. 事前固定の仮説と判定基準

### H-A：株価で判定するクロス円キャリー（日足）

- シグナルは毎日 17:00 EST の終値で判定します。使うのは S&P500 の日足終値だけで、約定する日の前日終値までです。
  - a：S&P500 が200日単純移動平均より上なら「リスクオン」とします。
  - b：a に加えて、S&P500 の20日実現ボラティリティ（年率）が、過去252日の中央値より低いこと。最初の期間は最低120個の値で中央値を計算します。
- ポジション：リスクオンなら、バスケットを買い持ちします。それ以外はノーポジションです。売買は、翌営業日 08:00 EST の H1 始値で行います。
- 配分：各ペアを60日ボラティリティの逆数で配分し、合計の建玉を1倍にします（これが「スケールなし」）。配分は週に1回見直します。報告用に、全期間の結果を事後に年率8%ボラへ換算しています。
- グループA：AUDJPY、NZDJPY、CADJPY の買い。グループB：EURJPY、GBPJPY、AUDUSD、NZDUSD の買い。
- ベンチマーク：同じバスケットを常に買い持ちしたものです。
- 基準：
  1. A/B × IS/OOS の4区分すべてで、ネット年率がプラス
  2. A+B 合算（同じボラで合成）の週次 t値が 2.0 以上
  3. 8%ボラで、累積リターン÷最大DD が 3 以上（A+B 合算で判定）
  4. 両グループで、買い持ちより Sharpe が高く、最大DD が小さい
  5. コスト2倍でも 1〜3 を満たす

### H-B：月末ヘッジ調整フロー（Melvin & Prins 2015）

- 月の最終営業日 T に判定します。米国株の月初来リターン −（相手国株の月初来リターン）を計算します。使うのは前日終値までです。プラスなら相手通貨を買い、マイナスなら売ります。
  - ペア：EURUSD↔DAX、GBPUSD↔FTSE、USDJPY↔日経（相手通貨の買い＝USDJPY の売り）、AUDUSD↔ASX
- a：T の 08:00 EST に入り、T のロンドン16時フィックスで手仕舞いします。フィックスの時刻は、英国冬時間なら 11:00 EST、夏時間なら 10:00 EST です（H1 始値）。
- b：T の2営業日前の 08:00 EST に入り、T のフィックスで手仕舞いします。シグナルには、エントリー日の前日終値までを使います。
- 1R ＝ エントリー時点の日足 ATR(14) × 0.5 です。損切りはなく、損益を測るための単位です。COST_PIPS を差し引いたネットで計算しています。
- 基準：
  1. IS と OOS の両方で平均R がプラス、かつ4ペア中3ペア以上でプラス
  2. 全取引合算の t値が 2.0 以上
  3. 合計R÷|最大DD(R)| が 3 以上
  4. N が 100 以上
  5. コスト1.5倍でも 1〜3 を満たす

### 6.3 スワップ

- スワップは含めていません。H-A で買う AUD・NZD・CAD の対円（と EUR・GBP の対円）は、2012〜2024年のほとんどの期間で、買いならスワップを受け取れる側でした。そのため、H-A の結果は実際より控えめ（保守的）です。
- ただし、スワップはノーポジションの日には付きません。常に買っている買い持ちのほうが、フィルター付きより多く受け取ります。**スワップを加えても、「フィルターが買い持ちに勝つ」という基準 (4) の判定は変わりません。**
- H-B は保有が1日以内（b でも約2日）なので、スワップの影響はわずかです。

## 7. 限界

- データ提供元は histdata だけで、他社データとの照合はしていません。株価指数は CFD 型の価格で、配当調整や先物ロールの扱いは不明です。GRXEUR には、上記のとおり別指数が混入しています。
- コストは固定の COST_PIPS です。指標発表時やロールオーバー時のスプレッドの広がり、約定のずれは、平均的な値でしか入れていません。
- H-A の8%ボラ換算は、全期間の実績ボラを使った事後換算です（報告用）。実際の運用で同じボラになるとは限りません。t値と Sharpe は、この換算の影響を受けません。
- 期間は約13年です。H-A の局面転換は約90〜130回で、統計的な検出力は限られます。
- 3ラウンドで合計50近いルールを試しました。仮にどれかが基準を満たしていても、多重検定を考えると、偶然である可能性を考える必要がありました。今回はどれも満たさなかったので、その判断は不要になりました。
- 「株価指数を使っても、この基準では利益の出るルールは見つからなかった」というのが結論です。どんな方法でも FX で利益が出ない、という証明ではありません。

  - r3_dq.py、r3_dq2.py：データ品質の確認
  - r3_common.py：共通処理
  - r3_ha.py、r3_ha_eval.py：H-A の計算と評価
  - r3_hb.py、r3_hb_eval.py：H-B の計算と評価
  - r3_diag.py：診断
  - r3_table.py：判定表の作成
  - r3_plot.py：資産曲線の図
- 出力（out/）
  - r3_dq.log、r3_ha*.log、r3_hb*.log、r3_diag.log：ログ
  - r3_pass_table.md／.csv：判定表
  - r3_ha_stats.csv、r3_ha_criteria.csv、r3_ha_yearly.csv：H-A の集計
  - r3_ha_daily.parquet、r3_ha_weekly.parquet、r3_ha_signals.parquet、r3_ha_contrib_*.parquet：H-A の日次・週次データ、シグナル、ペア別寄与
  - r3_hb_trades_*.parquet、r3_hb_criteria.csv：H-B の取引一覧と集計
  - r3_diag_equity.png：診断用の資産曲線（H-A の A+B を8%ボラで a・b・買い持ち、H-B の累積R）。合格案がないため、r3_equity.png は作っていません。
