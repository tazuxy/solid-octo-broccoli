# 第8ラウンド：探索の期間を「1か月」から「1年」に延ばしたエッジ探索ループ

対象データ：histdata の Bid のみの足（時刻は EST＝UTC−5 固定、夏時間なし。JST＝EST＋14時間）。FX 17通貨ペアと XAUUSD（2009年3月から）、2005〜2024年。
コスト：往復 0.5 pips（全 FX ペア）、XAUUSD は 0.30 USD。2倍のコストでも確認。スワップは入れていません。
R（リスクの単位）＝エントリー時点で確定している日足 ATR(14) の 0.25倍。
プログラムは第7ラウンドのもの（`r7_lib.py`、`r7_v2feat.py`、`r7_v2loop.py`、`r7_dev.py`）をそのまま読み込んで使い、探索の期間（窓）だけを1年に変えました（`r8_loop.py`）。

---

## 1. 結論

1. **新しい手法は見つかりませんでした。** 8年分の窓で 160個の候補を確かめ、「確認」を通った候補は **0個** です。そのため、ルール作り・凍結・最終テスト（2022〜2024年）には1つも進んでいません。**第8ラウンドでは最終テスト期間を一度も見ていません。**
2. 確認の基準（t値 3.4 以上）を超えたのは、**GBPCHF を 18:00〜19:00 EST（日本時間 朝8〜9時）に買う**ルール1つだけでした（t値 4.70）。ただし4つの期間のうちプラスは2つだけで、利益のすべてがロールオーバー（17:00 EST）の直後の1時間に集まっています。第7ラウンドで見た「17:00 に Bid が一時的に下がり、その後戻る」というデータ上の現象と同じものと考えられ、不合格です。このルールは第7ラウンドでも2回選ばれ、同じ理由で不合格でした。
3. **1年の窓にしても、当たりの率はほとんど良くなりませんでした。** 確認期間で平均がプラスになった候補の割合は 28%（1か月）→ 41%（1年）に上がり、t値の中央値も −0.67 → −0.46 と少しだけ改善しました。しかし、どちらもマイナスのままで、t値 2 を超えた候補は 160個中3個（1.9%）です。これは「本当の効果が何もない」場合に偶然で出る割合（約2%）と変わりません。
4. 比較できるのは引き続き**手法1（ゴトー日前日の USDJPY 買い、月末除く）だけ**です。組み合わせのポートフォリオは作れません。新しい EA も作っていません。

## 2. 1か月探索との違い

### 2.1 変えた点と変えていない点

| 項目 | 第7ラウンド（1か月） | 第8ラウンド（1年） |
|---|---|---|
| 探索の窓 | 2005-01〜2021-12 の204か月から12か月（乱数 seed 42） | 2005〜2021年の17年から最大8年（乱数 numpy default_rng(8)、重複なし） |
| 試した窓の順番 | 2012-03、2021-07 … | **2017、2021、2018、2007、2008、2012、2015、2009** |
| 窓の中で必要な回数 | 8回以上 | **30回以上** |
| 候補の数 | 窓ごとに上位20個 | 窓ごとに上位20個（同じ） |
| 確認の t値の基準 | 3.5（約260回の検定） | **3.4**（20個×8窓＝160回の検定、片側5%のボンフェローニ補正） |
| 確認に使う期間 | 発見の月以外の203か月 | **発見の年以外の16年** |
| 特徴の一覧（ライブラリ） | v2（ローソク足、インジケーター、水平線、ダウ理論、逆トレンドライン、組み合わせ）＋ v1（F1〜F9） | 同じ（新しい特徴は加えていない） |

そのほかの安全策は第7ラウンドのまま残しました。

- 16:55〜17:30 EST の時刻ではエントリーも決済もしない（Bid だけのデータで、ロールオーバー時の見かけの値動きを拾わないため）。利確・損切りの判定でも 17:00 の足を使わない。
- 発見の t値は「日ごとの損益」で計算し、ばらつきに下限を設ける。
- 窓の中でまったく同じ取引の集まりになるルールは、条件が少ないもの1つだけを残す。
- 確認の t値は「取引ごとの t値」と「日ごとの損益の t値」の小さい方を使う。

### 2.2 今回新しく加えた点（ご指示によるもの、および解釈）

- **ロールオーバーの時刻への集中のチェック**：エントリーまたは決済の時刻が 16時・17時・18時（EST）のどれか1つの時間に、合計利益の半分以上が集まっている候補は不合格。さらに、16:00〜18:59 にエントリーも決済もしない取引だけを取り出しても平均がプラス（30回以上）であることを条件にしました。候補ごとの時間別の利益は `r8_loop_log.md` に記録しています。
- **v1 の特徴（F1〜F9）の順位付け**：第7ラウンドでは v1 だけは「保有した1時間足ごと」の t値で順位を付けていました。今回はご指示の安全策（日ごとの損益で t値、ばらつきに下限）に合わせ、v1 も日ごとの損益の t値（下限は同じ種類の特徴の取引のばらつき）で順位を付け、「30回以上」は取引の回数で数えました。1年あれば取引の回数が十分にあるためです。
- 4つの期間（2005-08、2009-12、2013-16、2017-21）のうち発見の年を含む期間は、その年を除いて計算しました。

### 2.3 当たりの率の比較

| | 第7ラウンド（1か月×12） | 第8ラウンド（1年×8） |
|---|---|---|
| 確認した候補の数 | 240 | 160 |
| 確認期間で平均がプラス | 68個（28%） | 65個（41%） |
| 確認期間の t値の中央値 | −0.67 | −0.46 |
| t値 2 を超えた数 | 3個（1.3%） | 3個（1.9%） |
| t値 3.4 以上 | 2個（どちらも GBPCHF 18時台） | 1個（GBPCHF 18時台） |
| 「確認」 | 0個 | 0個 |
| 発見の t値と確認の t値の順位相関 | 0.16 | 0.05（ほぼ無関係） |

読み方：

- 1年の窓では、1つのルールあたりの回数が増えるので（窓の中の回数の中央値は年により 37〜183回）、偶然の当たりは減ると期待していました。確かに、確認期間で「マイナス」になる候補は減りました（コスト負けの度合いが小さくなった）。
- しかし、**「本物」といえる強さ（t値 3.4 以上）で再現した候補は、ロールオーバーのデータ上の現象を除くと 0個**です。発見の窓の中での t値（上位は 5〜9）と、他の年での t値の間には、ほとんど関係がありませんでした（順位相関 0.05）。つまり、1年の中で一番良く見えたルールでも、他の年での成績は予測できませんでした。
- 理由は、1年の窓の中でも 5,000〜19,000 通りのルールが「t値 2.5 超」の条件を満たしており、比べる数が多すぎるためです。窓を長くしても、これだけ多くのルールの中から一番を選べば、偶然で t値 5 以上のものが必ず出ます。

## 7. 限界

- **データは Bid だけ**です。スプレッドの変化（ロールオーバー、週明け、指標発表）は分かりません。ロールオーバーの時刻は除外・チェックしましたが、他の時刻のスプレッド拡大による見かけの利益が残っている可能性はあります。
- 4時間足については、第7ラウンドの実装どおり、ロールオーバーの除外をしていません（4時間足は 16:00 と 20:00 に始まるため、エントリー・決済の値段は 17:00 になりません）。ただし 16:00〜20:00 の4時間足の高値・安値は利確・損切りの判定に使われ、その場合の決済時刻は足の終わり（20:00）として記録されるため、今回の時刻チェックでは見えません。「確認」された候補がなかったので結果には影響しませんが、もし4時間足の利確/損切り型のルールが確認された場合は、別に調べる必要があります。
- コストは往復 0.5 pips（XAUUSD 0.30 USD）の固定の仮定です。クロス円や AUDNZD などでは、実際のスプレッドはこれより大きいことが多いです。スワップは入れていません。
- 探索は「1年の窓の中で一番良く見えたルール」を選ぶ方法です。今回の結果は、この方法（窓を1か月から1年に延ばしても）では、他の年でも再現するルールが見つからなかったことを示しています。ライブラリに含まれる特徴に効果が「まったくない」ことの証明ではありません。窓の中で偶然上位に来なかったルールは、確かめられていません。
- 確認の t値の基準 3.4 は 160回の検定を前提にしています。第7ラウンド（260回）と合わせると、確認の検定は通算 420回です。
- 試した8年は 2005〜2021年の17年のうち約半分です。残りの年を窓にすれば別の候補が出ますが、今回の当たりの率（t値 2 超が約2%、偶然と同じ水準）から見ると、結果が大きく変わる可能性は低いと考えます。
- v1 の特徴の順位付けを「日ごとの損益の t値」に変えた点（第2.2節）は、第7ラウンドと異なります。基準を厳しくする方向の変更で、結果を見る前に決めたものです。
