# 第6ラウンド：ゴトー日前日買い（E2）に条件を加えて検証する

対象：第4b ラウンドで唯一合格した E2（USDJPY 買い、ゴトー日 G の前営業日 D の 22:00 JST に買い、G の 09:55 JST に決済）。
データ：histdata の5分足・日足・4時間足（2005〜2024年、EST＝UTC−5 固定、Bid のみ）。JST＝EST＋14時間。
コスト：往復 0.5 pips（ご依頼者の仮定）。1.0 pip でも確認。**スワップは計算に入れていません。**
取引の作り方は第4b ラウンドと同じで、取引数 1,492回・損益の合計が第4b と完全に一致することを確認しました（別の独立した実装では、5分足が欠けた時刻を最大15分後の足で補ったため 1,514回・平均 +4.77 pips でした。今回は第4b の方式、つまり足がない日は見送り、に合わせています）。

---

## 1. 結論

1. 用意した15個の条件のうち、事前に決めた採用ルールを満たしたのは **「月末のゴトー日は取引しない」の1つだけ**でした。採用は選定期間（2005〜2014年）だけで決めました。
2. 確認期間（2015〜2024年）で一度だけ確かめた結果、**事前に決めた2つの確認条件を両方満たしました（「確認」）。**
   - 合計損益÷最大DD：条件なし 2.02 → 月末を除く 3.78
   - 月末のゴトー日の平均は −6.59 pips で、残りの平均 +3.71 pips より低い（選定期間と同じ向き）
3. **最終ルール＝E2 から「月末（最終営業日）のゴトー日」を除いたもの。** 2005〜2024年で 1,260回、1回平均 +6.22 pips（0.5 pips コスト後）、t値 4.63、合計÷最大DD 10.2。
4. **ただし、この「確認」は割り引いて受け取る必要があります。**
   - 第4b ラウンドの報告で、すでに2005〜2024年全体について「月末のゴトー日は弱い（−0.14R）」と見ていました。確認期間の結果の一部を事前に知っていたことになり、確認期間は完全な「未知のデータ」ではありません。
   - 月末を除いても、**確認期間だけでは t値 1.88 で、統計的に強いとは言えません**（条件なしの E2 は確認期間で t値 1.18 とさらに弱い）。この戦略の利益は 2005〜2014年に偏っています。
   - **利益が大きかった上位5%の取引を除くと、平均はほぼゼロ（+0.58 pips、t値 0.49）になります。** 少数の大きな値上がりに頼った戦略です。
5. 他の条件（上位足のトレンド、ボラティリティ、ADX、RSI、ボリンジャーバンド、前日高値からの距離、曜日、四半期末月）は、**どれも採用ルールを満たしませんでした。** 除外したい区分の平均がプラスだったか、その区分の取引数が少なすぎたためです。
6. 低いドローダウンを目指すなら、**最終ルール・損切りなし・1R＝資産の 0.25%**（年率 約4.0%、最大DD 約9.0%、モンテカルロの悪い方5%で約11%）か、**3R の損切り・0.5%**（年率 約2.2%、最大DD 約6.1%）が目安です。ただし、どの設定でも資産が最高値を更新できない期間が3〜5年あります。

## 2. 検証の手順（選定期間と確認期間を分けた理由）

**分けた理由**：同じデータで条件を選び、同じデータで成績を測ると、偶然うまく当てはまった条件でも良く見えてしまいます（過剰適合）。そこで、条件を選ぶデータ（選定期間）と、選んだ条件を一度だけ試すデータ（確認期間）を分けました。

- **選定期間**：ゴトー日 G が 2005年1月〜2014年12月（756回）
- **確認期間**：G が 2015年1月〜2024年12月（736回）

**手順（すべて、結果を見る前に固定し、時刻を記録）**

| 時刻（UTC、2026-11-04） | 内容 |
|---|---|
| 02:06:55 | 条件・区分・各条件の「除外してよい区分とその経済的な理由」・採用ルールを `r6_protocol.json` に保存（この時点で統計値は未計算） |
| 02:07:50 | 取引データと各条件の値を作成（区分別の成績はまだ未計算） |
| 02:08:09 | 選定期間だけで採用ルールを適用し、選んだ条件を `r6_frozen.json` に保存（確認期間の統計値は未計算） |
| 02:08:30 | 確認期間で一度だけ確認 → 「確認」 |

（記録は `r6_timeline.log`）

**条件の値はすべて、エントリー時点（08:00 EST）で確定しているデータだけを使用**しました。日足は 17:00 EST に終わるので、D の 08:00 EST に使えるのは前日 17:00 EST に終わった日足です。4時間足は 08:00 EST までに終わった足（04:00〜08:00 EST の足）です。週足は日足から作り、終わった週だけを使いました。

**採用ルール（選定期間のみ、0.5 pips コスト後、1回あたり pips）**

- 各条件について、**除外してよい区分を1つだけ、経済的な理由とともに先に決めました**（下表の「除外候補」）。理由のない区分は、成績が悪くても除外しません。これはご指示の (c) をより厳しくしたものです。
- (a) その区分の平均がマイナス、かつ残りの取引の t値が条件なしの t値（4.29）より高い
- (b) その区分が選定期間の取引の 15% 以上かつ 40回以上
- (c) 先に書いた経済的な理由がある
- 合計÷最大DD の改善幅で順位を付け、最大2つまで。2つ目は、1つ目で絞った取引の中で (a)(b) と改善を再確認。
- 区分の境目（SMA200、RSI 30/70 など）はご指示の値のままで、調整していません。

**確認期間のルール（一度だけ）**：絞り込んだルールの合計÷最大DD が条件なしより高く、かつ除外した区分の平均が残りの平均より低ければ「確認」。どちらかを満たさなければ「未確認」として条件なしのルールを推奨。

## 4. 最終ルール

- **USDJPY 買い。G＝ゴトー日（JST の 5・10・15・20・25・30日、土日なら直前の金曜日）。ただし月末（その月の最終営業日）のゴトー日は取引しない**（30日が最終営業日の場合も月末として除外）。
- D＝G の前の営業日。**D の 22:00 JST に買い、G の 09:55 JST に決済。** 日本の祝日は考慮していません（バックテストと同じ）。
- 2005〜2024年（0.5 pips コスト後）：1,260回、平均 +6.22 pips、t値 4.63、合計 +7,838 pips、最大DD −769 pips、合計÷最大DD 10.2、最長の停滞 1,174日。
- 1.0 pip コスト：平均 +5.72 pips、t値 4.26、合計÷最大DD 8.8。
- 年別（0.5 pips、pips 合計）：マイナスの年は 2007（−485）、2018（−114）、2023（−269）の3年。条件なしでは 7年がマイナス（`r6_yearly.csv`）。2023年は USDJPY のデータ欠損が多く、取引数が少ないです。

## 7. EA の変更点（`r6_EA.mq5`）

- `r4b_EA.mq5` をコピーし、次の入力を追加しました。時刻・夏時間の処理は変更していません。
  - `InpSkipMonthEndG = true`（初期値オン）：G がその月の最終営業日なら見送り。`false` にすると第4b の E2 と同じ動きになります。
- 追加した関数：`IsLastBusinessDayOfMonth()`（土日と `InpExtraHolidays` だけを休日とする、既存の暦と同じ判定）。
- **新しいインジケーターのハンドルはありません**（採用した条件は暦だけで決まるため）。採用しなかった条件（SMA200、ADX、RSI、ボリンジャーなど）は、使うと過剰適合につながるため、あえて入力に入れていません。
- 前提・注意：
  1. ここではコンパイルしていません。MetaEditor で確認が必要です。
  2. `InpExtraHolidays` を空にすればバックテストと同じ暦です。日本の祝日を入れると、月末やゴトー日の日付が変わります。
  3. 30日が月の最終営業日の場合は「月末」として見送ります（バックテストと同じ）。
  4. 既存の注意（ブローカーの GMT オフセット、日足 ATR の違い、スワップ未計算など）はそのままです。将来インジケーターを追加する場合、MT5 の iATR は単純平均（バックテストはワイルダー方式）、iADX はワイルダー方式ではない（iADXWilder を使う）、ブローカーの4時間足の区切りはバックテスト（00:00 EST 基準）と異なる、という点に注意が必要です。

## 8. 多重検定と限界

- **調べた区分の数**：1段目 15条件・45区分（データ不足の「NA」を除く）、うち除外候補を決めた条件は14個。2段目（月末を除いた後）13条件・38区分。**合計 83区分、除外の判定は 27回**です。
- 選定期間だけで見ると、月末と残りの差の t値は 2.20（片側 p 約0.014）で、14回の判定で補正すると（ボンフェローニ）有意ではありません（補正後 p 約0.2）。無作為に同じ数を除く比較でも、改善の大きさは約9%の確率で偶然に起こる程度でした。つまり、**選定期間だけでは「月末」は偶然の可能性も十分にある候補**でした。
- 確認期間では同じ向きの差（t値 2.27、無作為比較で約2%）が出ました。一度だけの確認としては良い結果ですが、**月末が弱いことは第4b の全期間の結果で既に見ていた**ため、完全に独立した確認ではありません。DOW1（月曜）・DOW2（ゴトー日の種類）・HTF5a（5日の下落）は、第4b で全期間の結果を見ている点で同じ問題があります。
- E2 そのものも、第0〜4b ラウンドの多くの試行の後に見つかったものです。今回の条件探しは、その上にさらに 27回の判定を重ねています。
- **E2 の利益は 2005〜2014年に偏っています。** 2015〜2024年は、条件なしで t値 1.18、月末を除いても 1.88 で、それだけでは統計的に強いとは言えません。
- 上位5%の取引を除くと平均はほぼゼロです。少数の大きな値上がりに頼っています。
- スワップは含めていません。祝日（日本の祝日）は考慮していません。データは Bid のみで、コストは往復 0.5 pips の仮定です。2023年は USDJPY のデータ欠損が多く、取引数が少ないです。
- 株価指数のデータ（2011年以降のみ）は、選定にも確認にも使っていません。
- **お勧め**：月末除外は「入れても良いが、効果は小さめに見積もる」程度の条件と考えてください。2025年以降のデータ、またはデモ口座で、条件なしと月末除外の両方を並べて記録し、確認することをお勧めします。
