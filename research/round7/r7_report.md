# 第7ラウンド：自動の「エッジ探索ループ」（1か月で見つけ、他の月で確かめ、最後に未使用の期間で1回だけ試す）

対象データ：histdata の Bid のみの足（時刻は EST＝UTC−5 固定、夏時間なし。JST＝EST＋14時間）。FX 17通貨ペアの5分足・15分足・1時間足・4時間足・日足と XAUUSD（2009年3月から）、2005〜2024年。
コスト：往復 0.5 pips（全 FX ペア、ご依頼者の仮定）。XAUUSD は 0.30 USD。2倍のコストでも確認。スワップは入れていません。
R（リスクの単位）＝エントリー時点で確定している日足 ATR(14) の 0.25倍。

---

## 1. 結論

1. **新しい手法（手法2・手法3）は見つかりませんでした。** 採用は 0件で、比較できるのは手法1（ゴトー日前日の USDJPY 買い、月末除く）だけです。
2. **最初のライブラリ（v1：ご指示の F1〜F9）**で2か月試したところ、3つの候補が「確認」を通り、そのうち2つを凍結して最終テスト期間（2022〜2024年）で1回ずつ評価しました。数値の上では採用基準を満たしました。**しかし調べたところ、利益は 17:00 EST（NY 終値の時刻、ロールオーバー）に Bid の値が一時的に下がる現象から来ていました。** この時刻はスプレッドが大きく広がるため、Bid だけのデータでは利益に見えても、実際の取引では得られません。そのため**両方とも不採用**にしました（詳細は第5章）。
3. 途中で仕様が変わり、**ライブラリ v2**（ローソク足、インジケーター、水平線、ダウ理論、逆トレンドラインのブレイク、それらの組み合わせ、17ペア共通ルール）で、同じ12か月を最初からやり直しました。**240個の候補を他の月で確認しましたが、「確認」は 0件でした。** 確認期間で平均がプラスだったのは 240個中 68個（28%）、確認期間の t値の中央値は約 −0.7 です。1か月で良く見えたルールのほとんどは、他の月ではコスト負けでした。
4. ご提案の**逆トレンドラインのブレイク（押し目の終わりを狙う順張り）**も、ループの外で 2005〜2021年全体を見ましたが、1時間足・15分足とも、17ペア合計で**コストを引く前の段階からマイナス**でした（第4章）。
5. 多重検定のために数えた確認テストの数は**合計 260回**（v1 20回＋v2 240回）です。最終テスト期間（2022〜2024年）を見たのは**2回**だけで、2回とも上記の v1 のロールオーバー由来の候補でした。
6. 手法1（参考）：2005〜2024年 1,260回、平均 +6.22 pips（+0.25R）、t値 4.68、1回 0.25% のリスクで年率 4.0%・最大DD −9.0%。ただし手法1は以前のラウンドで 2022〜2024年もすでに見ているため、この期間は手法1にとって「未使用の期間」ではありません（2022〜2024年だけでは 171回、平均 +4.69 pips、t値 1.02）。

## 2. ループの手順と安全策

### 2.1 期間の分け方と、分けた理由

| 期間 | 使い方 |
|---|---|
| 2005年1月〜2021年12月（204か月） | 発見（1か月だけ）、確認（残りの203か月）、ルール作り（全体） |
| **2022年1月〜2024年12月** | **最終テスト期間。** ルールを凍結してファイルに保存し、時刻を記録した後に、1つの手法につき1回だけ見る |

同じデータでルールを選び、同じデータで成績を測ると、偶然うまく当てはまったルールでも良く見えてしまいます（過剰適合）。特に今回は数千〜数万のルールを機械的に探すため、偶然の当たりが必ず出ます。そこで、(1) 1か月だけで候補を選び、(2) 残りの203か月で確かめ、(3) さらに一度も使っていない3年間で最後に1回だけ確かめる、という三段構えにしました。
最終テスト期間のデータは、プログラムの中で読み込みを禁止しました（ルールを凍結したファイルがないと、2022年以降の足を読み込めない仕組み）。読み込んだ時刻は `r7_holdout_timeline.log` に残っています。

### 2.2 1か月ごとの手順

1. **月を選ぶ**：2005-01〜2021-12 の204か月から、乱数（numpy default_rng(42)）で重複なしに12か月を選びました。順番は 2012-03、2021-07、2017-07、2013-11、2015-08、2019-03、2006-06、2012-02、2006-08、2016-08、2021-08、2008-05。
2. **発見（その1か月だけ）**：決めておいた特徴の一覧（ライブラリ）を、全ペア・全方向について調べ、その月の平均の損益（コスト後）と t値を計算。その月に8回以上起きたものだけを対象に、t値の高い順に v1 は上位10個、v2 は上位20個を候補にしました（売り買いの向きは発見した月の結果で固定）。
3. **確認（残りの203か月）**：次のすべてを満たせば「確認」。
   - コスト後の平均がプラス（pips でも R でも）
   - t値が v1 は 3.2 以上、v2 は 3.5 以上
   - 4つの期間（2005-08、2009-12、2013-16、2017-21）のうち3つ以上でプラス
   - コスト2倍でもプラス
   - 17ペア共通ルールは、さらに 60% 以上のペアでプラス
4. **ルール作り（確認された候補だけ）**：損切り（なし／2R／3R）を選び、追加の条件は最大1つ。条件は 2005〜2014年で選び、凍結してから 2015〜2021年で確かめる（第6ラウンドと同じ方式）。手法1や先に試した手法と日々の損益の相関が 0.5 を超えるものは同じものとみなして飛ばす。
5. **凍結と最終テスト**：ルールを `r7_method{N}_frozen.json` に保存し、時刻を記録してから 2022〜2024年を1回だけ評価。採用基準は「最終テスト期間の平均がプラス」「その平均が 2005〜2021年の平均の 25% 以上」「2005〜2024年全体の t値 3.0 以上」「合計÷最大DD が 3 以上」。
6. 新しい手法が2つ採用されるか、12か月を試したら終了。

### 2.3 多重検定の扱い

- 1か月の中では数千〜1万程度のルールを比べるので、上位のルールはほぼ偶然です。発見の段階では「本物かどうか」は判断せず、候補を選ぶだけです。
- 本当の判定は確認の段階で行い、**確認したルールの数（v1 20、v2 240、合計 260）**を数えました。t値の基準 3.2（v1）・3.5（v2）は、この回数で偶然に合格する確率を約5%に抑えるための値（ボンフェローニ補正、片側）です。
- 確認の期間は発見の月を除いた全期間なので、1つのルールにつき1回の検定になっています。

### 2.4 途中で加えた安全策（ご指示に追加したもの。すべて理由とともにログに記録）

| 追加した点 | 理由 |
|---|---|
| **ロールオーバーの除外**：16:55〜17:30 EST の時刻で、エントリーや決済の値段を取らない（1時間足では 17:00 を 18:00 にずらす。17:00 の1時間足の高値・安値は、利確・損切りの判定に使わない） | v1 で見つかった「確認」がすべてこの時刻の Bid の一時的な下落によるもので、0.5 pips のコストの仮定が成り立たない時間帯だったため（第5章） |
| 発見の t値は、その月の**日ごとの損益**で計算 | 状態型のインジケーター（例：「価格が EMA200 より上」）は毎時間成り立つため、保有期間が重なり、17ペア共通ルールではペア同士も同じ時刻に動きます。そのまま数えると t値が大きく見えすぎるため |
| 発見の t値の計算で、ばらつき（標準偏差）に下限を設定（その月・その時間足の全イベントのばらつき） | 少数の利確がすべて同じ幅で当たると、ばらつきがほぼゼロになり t値が 100 を超えるなど、意味のない順位になったため |
| 発見の月の中で**まったく同じ取引の集まり**になるルールは、条件が少ないもの1つだけを残す | 意味のない条件を付け足しただけの、ほぼ同じルールが上位を埋めてしまうため |
| 確認の t値は「取引ごとの t値」と「日ごとの損益の t値」の**小さい方**を使う | 17ペア共通ルールでは同じ日に複数ペアで取引が重なるため |
| 確認・ルール作りでは、同じペアで同時に持つポジションは1つ（前の取引が終わるまで次は見送り） | 実際の取引と同じにするため |

### 2.5 解釈が必要だった点

- F2（曜日×4時間）・F3（日付×時間帯）・F8（週の始まり）は、取引の回数で数えると1か月に4〜5回しかなく「8回以上」を満たせません。そこで発見の段階では**保有した1時間足の本数**を回数として数え（加えて取引日が3日以上）、確認の段階では実際の取引単位で計算しました。
- F7（米ドル指数の先行）：ドルを含まないクロス円などは「前の1時間にドルが上がったらクロスを買う」を「順張り」と呼び、逆を「逆張り」としました（どちらも試すので、名前だけの違いです）。
- 手法1と同じ効果の除外：USDJPY の 08:00〜10:00 JST の時間帯（F1 の 18時・19時 EST）、16〜20時 EST の4時間ブロック、F3 のアジア時間（仲値の 09:55 JST を含む）を対象から外しました。
- 逆トレンドライン（T）の「押し目が崩れていない」は、文字どおり「終値が押し目の最安値より上」としました。最初に「上昇の起点の安値を割っていない」と解釈したところ、条件を満たす場面が17年で数十回しかなかったためです。トレンドの判定は上位足（4時間足・日足のダウ理論、4時間足の EMA200）で行っています。

**不採用の理由**（2005〜2021年のデータだけで確認。`r7_rollover_diag.log`、`r7_rollover_diag2.log`）

- 月〜木曜の 16:00 EST の Bid を基準にした平均の変化（pips）：AUDNZD は 16:55 で −0.27、**17:00 で −2.26**、17:30 で −0.75。EURAUD は −0.99 → **−2.27** → +0.04。GBPCHF は −0.38 → **−2.92**。EURCHF −1.56、EURGBP −1.31。主要通貨の EURUSD は −0.35 と小さい。米国の夏時間・冬時間のどちらでも同じでした。
- 同じ時刻に5分足の高値−安値の幅が約1.7倍に広がります（スプレッドが広がるため）。
- つまり、Bid だけのデータでは、17:00 に「売りを買い戻す」「買う」と、一時的に下がった Bid で約定したように見えます。実際には Ask で約定し、この時刻の Ask は Bid より数 pips 以上高いのが普通です。0.5 pips というコストの仮定は、この時刻には当てはまりません。2つの候補の利益（約2〜3 pips）は、この下落の幅とほぼ同じです。
- 最終テスト期間でも同じ結果が出たのは、データの性質（ロールオーバー時の Bid の下落）が 2022〜2024年も変わらないためで、取引で得られる利益の証拠にはなりません。

## 7. 限界

- **データは Bid だけ**です。スプレッドの変化（ロールオーバー、週明け、指標発表）は分かりません。今回はロールオーバーの時刻だけを除きましたが、他の時刻のスプレッド拡大による見かけの利益が残っている可能性はあります。
- コストは往復 0.5 pips（XAUUSD 0.30 USD）の固定の仮定です。クロス円や AUDNZD などでは、実際のスプレッドはこれより大きいことが多いです。スワップは入れていません。
- 発見を1か月で行う方法は、ご指示どおりですが、1か月に8回程度のデータでは偶然の当たりがほとんどです。今回の結果（240候補中「確認」0）は、この方法で見つかるのは主に偶然である、ということを示しています。「どの特徴にも効果がない」ことの証明ではありません。発見の月に偶然上位に来なかったルールは、確かめられていません。
- 途中でいくつかの安全策（ロールオーバーの除外、日ごとの損益での t値など）を加えました。どれも基準を厳しくする方向で、v1 の結果を見た後に決めたものです。記録は `r7_loop_log.md` にあります。
- 仕様の解釈（第2.5節）によって結果が変わる可能性があります。特に逆トレンドラインの定義（スイングの取り方、「押し目が崩れていない」の意味）は、別の定義を試していません。
- 最終テスト期間は2回使いました（v1 の2候補）。v2 では使っていません。将来の検証に、2022〜2024年はまだ「ほぼ未使用」として残っています（ただし手法1と v1 の2候補では使用済み）。
- 手法1自体も、利益の多くが少数の大きな値上がりに頼っており（第6ラウンド参照）、2015年以降は統計的に強くありません。
